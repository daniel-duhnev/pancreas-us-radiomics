# Machine Migration Guide

A complete step-by-step guide for migrating this project to a new laptop or machine and working with Claude Code agents on the other side.

**Last verified:** 2026-05-27
**Source machine:** macOS (Apple Silicon, M-series), Miniconda, thesis_env Python 3.9.25
**Target platforms:** macOS, WSL2 (Ubuntu on Windows), native Linux

---

## Overview: What Lives Where

| Component | In git? | Size | How to transfer |
|-----------|---------|------|-----------------|
| All code, notebooks, thesis LaTeX, docs | Yes | ~15 MB | `git clone` |
| Thesis figures (`thesis/Figures/`) | Yes | ~2 MB | `git clone` |
| `environment.yml` | Yes | — | `git clone` (but see caveats below) |


### Step 4: Set up Python environment

**IMPORTANT:** The `environment.yml` in the repo was exported from a Linux machine. It contains Linux-specific packages (`_libgcc_mutex`, `ld_impl_linux-64`, etc.) and WILL FAIL on macOS with `conda env create -f environment.yml`.

#### Option A: Install from package names only (recommended for macOS)

```bash
conda create -n thesis_env python=3.9 -y
conda activate thesis_env

pip install numpy==2.0.2 pandas==2.3.3 matplotlib==3.9.4 \
    opencv-python==4.13.0.92 pydicom==2.4.4 SimpleITK==2.5.3 \
    pyradiomics==3.1.0 scikit-learn scipy \
    ipykernel jupyter-client jupyter-core

python -m ipykernel install --user --name thesis_env --display-name "thesis_env"
```

Key packages and their purposes:
- `pydicom` — loading DICOM files
- `opencv-python` — image processing (contour detection, morphology)
- `SimpleITK` — image format conversion for PyRadiomics
- `pyradiomics` — radiomics feature extraction
- `scikit-learn` — ML pipeline (StandardScaler, SelectKBest, classifiers, GridSearchCV)
- `scipy` — statistical tests (Mann-Whitney, Shapiro-Wilk, Wilcoxon)
- `pandas` / `numpy` / `matplotlib` — data manipulation and plotting

#### Option B: If on Linux (environment.yml will work)

```bash
conda env create -f environment.yml
conda activate thesis_env
python -m ipykernel install --user --name thesis_env --display-name "thesis_env"
```

#### Verification:

```bash
conda activate thesis_env
python -c "import cv2, pydicom, numpy as np, pandas as pd, SimpleITK as sitk, radiomics; print('All imports OK')"
```

## Potential Hurdles and Solutions

### Hurdle 1: environment.yml fails on macOS

**Symptom:** `ResolvePackageNotFound: _libgcc_mutex`, or similar Linux-only package errors.

**Solution:** Use Option A from Step 4 (install packages manually with pip). The key packages are all cross-platform via pip.

---

### Hurdle 2: Nested zip folder structure

**Symptom:** Notebooks fail with "FileNotFoundError" because the path has an extra level (e.g., `data/data/PANCREAS_2/...`).

**Solution:** Check that `data/PANCREAS_2/PANCREAS_2/` exists directly. If your zip created `data/data/...`, move the contents up one level:
```bash
mv data/data/* data/
rmdir data/data
```

---

### Hurdle 3: DICOM files have no file extension

**Symptom:** You see files with long numeric names like `1.3.6.1.4.1.14519.5.2.1...` — no `.dcm` extension.

**This is normal.** The notebook code handles this. It finds the first file in each study's date folder regardless of extension. These ARE DICOM files — pydicom reads them fine.

---

### Hurdle 4: Git SSH authentication on new machine

**Symptom:** `git clone git@github.com:...` fails with "Permission denied (publickey)."

**Solution:** Either:
1. Clone with HTTPS instead: `git clone https://github.com/daniel-duhnev/pancreas-us-radiomics.git`
2. Or generate a new SSH key and add it to GitHub:
```bash
ssh-keygen -t ed25519 -C "daniduhnev@gmail.com"
cat ~/.ssh/id_ed25519.pub
# Add this to GitHub → Settings → SSH Keys
```

---

### Hurdle 5: PyRadiomics version mismatch

**Symptom:** Feature extraction produces different numbers or different feature counts.

**Solution:** Must use PyRadiomics 3.x (specifically 3.1.0 or 3.0.1). Check with:
```bash
python -c "import radiomics; print(radiomics.__version__)"
# Must be 3.x
```

---

### Hurdle 6: scikit-learn version differences

**Symptom:** ML results differ slightly between machines.

**Explanation:** Minor sklearn version differences can produce slightly different results for randomised operations (even with `random_state=42`) due to internal implementation changes. For reproducing EXACT numbers, pin sklearn:
```bash
pip install scikit-learn==1.6.1  # or whatever version matches
```

Check current version:
```bash
python -c "import sklearn; print(sklearn.__version__)"
```

## Platform-Specific Notes: WSL2 (Ubuntu on Windows)

WSL2 is the most likely alternative platform. It introduces several specific issues that don't apply to native macOS or Linux.

### WSL Rule 1: Work in the Linux filesystem, NOT /mnt/c/

This is the single most important rule. The Windows-mounted filesystem (`/mnt/c/Users/...`) has terrible I/O performance from WSL — git operations, Python imports, and notebook execution will be 5-10x slower.

```bash
# GOOD: clone into your WSL home directory
cd ~
git clone <repo-url>
cd pancreas-us-radiomics

# BAD: working on the Windows filesystem
cd /mnt/c/Users/Daniel/repos/pancreas-us-radiomics  # DO NOT DO THIS
```

The project, data, conda env — everything should live under `~/` (the ext4 Linux filesystem inside WSL).

### WSL Rule 2: Download data on Windows, then move into WSL

You can't easily download from Google Drive inside WSL (no browser). Instead:

1. Download the zip on Windows (via Chrome/Edge) — it lands in e.g. `C:\Users\Daniel\Downloads\data.zip`
2. Move it into WSL:
```bash
# From inside WSL:
cp /mnt/c/Users/Daniel/Downloads/data.zip ~/pancreas-us-radiomics/
cd ~/pancreas-us-radiomics
unzip data.zip -d data/
rm data.zip
```

Or use `explorer.exe .` from WSL to open the current folder in Windows Explorer, then drag files in — but for large zips, the `cp` from `/mnt/c/` approach is more reliable.

### WSL Rule 3: Install system dependencies for OpenCV

On WSL (Ubuntu), `opencv-python` requires system libraries that aren't installed by default:

```bash
sudo apt update
sudo apt install -y libgl1-mesa-glx libglib2.0-0 libsm6 libxext6 libxrender-dev
```

Without these, `import cv2` will fail with `ImportError: libGL.so.1: cannot open shared object file`.

### WSL Rule 4: The environment.yml WILL work on WSL

Since WSL2 is Linux (Ubuntu), the `environment.yml` with its Linux-specific packages (`_libgcc_mutex`, `ld_impl_linux-64`) should resolve correctly:

```bash
conda env create -f environment.yml
conda activate thesis_env
python -m ipykernel install --user --name thesis_env --display-name "thesis_env"
```

If it fails (e.g., architecture mismatch on ARM), fall back to the manual pip install (Option A in Step 4).

### WSL Rule 5: Git line endings

Configure git to NOT convert line endings. This prevents corruption of notebook JSON and CSV files:

```bash
git config --global core.autocrlf input
```

If you already cloned and see `\r\n` issues:
```bash
git rm --cached -r .
git reset --hard
```

### WSL Rule 6: VS Code + WSL Remote for Jupyter

To run notebooks in VS Code with the WSL Python:

1. Install the "WSL" extension in VS Code (on Windows side)
2. Open VS Code, press `Ctrl+Shift+P` → "WSL: Connect to WSL"
3. Open the project folder from within the WSL session (`~/pancreas-us-radiomics`)
4. Select kernel: `thesis_env (Python 3.9.25)` — it should appear if you ran `ipykernel install`

If the kernel doesn't appear, from WSL terminal:
```bash
conda activate thesis_env
python -m ipykernel install --user --name thesis_env --display-name "thesis_env"
```
Then restart VS Code.

### WSL Rule 7: LaTeX in WSL

```bash
sudo apt install texlive-full latexmk
# This is ~4 GB and takes several minutes

cd thesis
latexmk -pdf MasterThesis.tex
```

Alternatively, compile on the Windows side if you have MiKTeX/TeX Live installed there — but it's simpler to keep everything in WSL.

### WSL Rule 8: Claude Code installation on WSL

Claude Code runs inside WSL as a normal Linux CLI tool:

```bash
# Install Node.js (if not already present)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Install Claude Code
npm install -g @anthropic-ai/claude-code

# Run from the project directory
cd ~/pancreas-us-radiomics
claude
```

The agent will read `CLAUDE.md` automatically. The Python path in `CLAUDE.md` will be wrong (it says `/opt/homebrew/...` which is macOS-specific). Update it:
```bash
conda activate thesis_env
which python
# Output will be something like: /home/daniel/miniconda3/envs/thesis_env/bin/python
# Update CLAUDE.md with this path
```

### WSL Rule 9: Miniconda installation on WSL

If Miniconda isn't installed yet in WSL:

```bash
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
# Accept defaults, say yes to init

# Restart shell or:
source ~/.bashrc
conda --version
```

### WSL Rule 10: Disk space

WSL2's virtual disk grows dynamically but check you have enough space:
- Conda env: ~2 GB
- Data: ~800 MB
- TeX Live: ~4 GB (if installed)
- Total needed: ~7 GB free minimum

Check with: `df -h /` from inside WSL.

## Platform-Specific Notes: macOS (Apple Silicon / Intel)

### macOS Note 1: environment.yml won't work

The `environment.yml` is Linux-specific. Use Option A (manual pip install) from Step 4.

### macOS Note 2: Miniconda paths

- Apple Silicon (M1/M2/M3): Miniconda installs to `/opt/homebrew/Caskroom/miniconda/base/` (if via brew) or `~/miniconda3/`
- Intel Mac: typically `~/miniconda3/` or `/usr/local/Caskroom/miniconda/base/`

The `thesis_env` Python will be at: `<miniconda_base>/envs/thesis_env/bin/python`

### macOS Note 3: LaTeX via brew

```bash
brew install --cask mactex
# Adds to PATH automatically after terminal restart
latexmk --version
```

### macOS Note 4: No system library issues

Unlike WSL, `opencv-python` works out of the box on macOS — no extra system packages needed.
