The \texttt{force2D} setting was required because the input images are single 2D ultrasound slices stored as 3D arrays with depth $= 1$. Without this setting, PyRadiomics attempts 3D co-occurrence calculations that fail on single-slice volumes. Shape features were disabled because the region-of-interest masks were manually drawn by clinicians to delineate the pancreas graft boundary; shape features would therefore reflect annotation style rather than tissue properties.

The \texttt{normalize} setting applies a per-image $z$-score transformation prior to feature computation: each image's pixel intensities are centred to zero mean and unit variance, then scaled by a factor of 100 (\texttt{normalizeScale}). Outlier pixels beyond 3 standard deviations are clipped (\texttt{removeOutliers}). This normalisation is essential for ultrasound radiomics because ultrasound images lack a standardised intensity scale---unlike Hounsfield units in CT---and differences in gain, depth, and probe pressure between acquisitions produce varying absolute intensity ranges that would otherwise confound texture features.

The bin width of 25 discretises the normalised intensity values into bins of width 25 for texture matrix computation. With the normalise scale of 100, typical pixel values range from approximately $-300$ to $+300$, yielding approximately 24 bins. The Image Biomarker Standardisation Initiative (IBSI) \cite{zwanenburg2020} provides reference values for IBSI-compliant extraction, enabling comparison with other studies.
